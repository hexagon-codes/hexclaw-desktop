# 1. experimental 分层：这是你目前最正确的决策

这一条非常关键。

你现在：

```json
{
  "layers": [...],
  "triggers": [...],
  "commands": [...],

  "experimental": {
    "hooks": [...],
    "agents": [...],
    "scripts": [...]
  }
}
```

本质上已经形成：

```text
Stable Contract Layer
vs
Experimental Extension Layer
```

这会极大降低：

> “Schema 反向锁死 Runtime”

的问题。

这是大型平台都会经历的阶段。

例如：

- Kubernetes alpha/beta/stable API
- Chrome experimental APIs
- VSCode proposed APIs
- MCP experimental capability

本质都是：

> Runtime 还没稳定，
> 但生态需要提前预留扩展点。

你现在这个方向是对的。

# 2. commands 保持 stable 是正确的

你特意写：

> commands 是 stable（Claude Code 兼容已验证）

这是合理的。

因为从 Anthropic 官方演化来看：

```
.claude/commands/*.md
```

实际上已经逐渐收敛进：

> Skills Invocation Layer。([Claude](https://code.claude.com/docs/en/skills?utm_source=chatgpt.com))

也就是说：

commands 并不是“高级 runtime”。

而是：

> prompt routing abstraction。

这个复杂度远低于：

- hooks lifecycle
- agents delegation
- sandbox scripts

所以：

```text
commands = stable
hooks/agents/scripts = experimental
```

这个分层是合理的。

# 7. 但这里有一个未来会出现的“分叉点”

这个点你之后一定会遇到。

------

## 当前你定义：

```text
scripts/hooks/agents
=
experimental structure only
```

问题在于：

一旦生态开始真正使用这些字段。

你会进入两条路线分叉：

------

# 路线 A：Skill remains declarative

即：

```text
Skill
=
declaration only
```

真正执行：

全部交给 Runtime。

优点：

- 干净
- 可控
- 安全

缺点：

- Skill 表达力有限

------

# 路线 B：Skill becomes executable package

即：

```text
Skill
=
portable runtime unit
```

优点：

- 强大
- 社区爆发力高

缺点：

- 复杂度指数上升

------

现在 Anthropic 其实正在往 B 演化。([GitHub](https://github.com/anthropics/skills?utm_source=chatgpt.com))

尤其：

- scripts
- hooks
- subagents
- routines
- loops

已经说明：

Claude Code Skill 不再只是 prompt bundle。

------

但你目前：

还处在一个非常好的位置：

> 可以继续保持 A，
> 同时为 B 预留结构。

这是最健康的状态。

# 8. 我现在最建议你新增的一条“宪法规则”

建议直接写进：

# Compatibility Philosophy

------

## 建议新增：

```text
Runtime MAY ignore unsupported fields.
```

这是极重要的一条。

例如：

```json
{
  "experimental": {
    "agents": [...]
  }
}
```

如果 Runtime 当前不支持：

- 不报错
- 不中断
- 不失败

而是：

```text
ignore + warn
```

否则：

未来：

- Runtime fragmentation
- capability mismatch
- package incompatibility

会快速出现。

------

这个思想其实非常像：

- HTML progressive enhancement
- browser feature detection
- Kubernetes optional capability

对 Agent Runtime 非常重要。
