## 安装与首次启动

### 系统要求

| 平台 | 运行要求 |
|------|---------|
| macOS | 使用当前随包的本地推理和文档渲染组件需要 14 (Sonoma) 及以上；Apple Silicon / Intel |
| Windows | 10 (1809) 及以上 |
| Linux | 发布构建使用 Ubuntu 22.04；运行环境需具备 WebKitGTK 4.1 等 Tauri 依赖 |

应用外壳配置的 macOS 11 下限不代表随包组件的兼容范围。[Ollama 的 macOS 要求](https://docs.ollama.com/macos)与 [Tauri Linux 发行依赖](https://v2.tauri.app/distribute/debian/)分别说明对应运行条件。

### 安装方式

**macOS 一键安装（推荐）**

```bash
curl -fsSL https://raw.githubusercontent.com/hexagon-codes/hexclaw-desktop/bb3c12ec91eec91798b67c292bc8c85c4481dc2b/install.sh | bash
```

脚本自动识别 Apple Silicon / Intel，下载已公开的安装包（含预发布版）并安装到 `/Applications/HexClaw.app`。

**macOS (Homebrew)**

```bash
brew tap hexagon-codes/tap
brew install --cask hexclaw
```

**macOS / Windows / Linux (手动下载)**

1. 前往 [GitHub Releases](https://github.com/hexagon-codes/hexclaw-desktop/releases) 页面
2. 下载对应平台安装包：
   - macOS: `.dmg` 文件，双击打开后拖入 Applications
   - Windows: `.exe`（NSIS）安装程序
   - Linux: `.deb` (Debian/Ubuntu) 或 `.AppImage`
3. 启动 HexClaw

### 首次启动

1. **选择服务** — 首次设置中使用本机服务，或填写云端 HexClaw 服务地址和访问令牌。
2. **确认模型** — 当前服务已有可用默认模型时可直接发起任务；未配置时再设置 Provider 和模型。在线模型填写所需凭据和地址并测试连接，本地模型确认 Ollama 与已下载模型可用，无需云端 API Key。
3. **开始对话** — 进入聊天页面，发送第一条消息或附件。

本机与云端分别保存会话、模型配置和业务数据，切换服务不会自动迁移或合并。未配置模型时，服务仍可启动；AI 任务需要可用模型，本地 Ollama 模型无需云端 API Key。

### macOS 安全提示

首次打开可能弹出"无法验证开发者"提示。解决方法：

- **方法 A**: 系统设置 → 隐私与安全性 → 找到 HexClaw → 点击"仍要打开"
- **方法 B**: 终端执行 `xattr -cr /Applications/HexClaw.app`

## 自动更新发布

HexClaw 已接入 Tauri updater。应用启动后会静默检查更新，用户也可以在 **关于** 页面手动检查并安装更新。

如果你只是本地打包测试：

- 不需要 updater 私钥
- 手动触发 `Release` 并指定固定提交 SHA 构建测试安装包；缺少签名私钥时自动关闭 updater 制品生成
- 这类包可以手动安装；未生成签名更新制品的版本不能作为自动更新目标，已安装应用仍可检查并安装后续有效签名版本
- macOS 保持未签名 DMG，通过现有 Homebrew Cask 分发；不要求 Apple Developer ID 签名或公证

如果你要发布正式自动更新版本：

- 必须配置 Tauri updater 签名私钥
- 必须保留 [src-tauri/tauri.conf.json](../src-tauri/tauri.conf.json) 中的 `plugins.updater.pubkey`
- 必须通过 tag 触发 `Release` 工作流，由它生成带签名的 updater 制品和 `latest.json`
- Tauri updater 制品签名与 Apple 代码签名独立；macOS 仍保持未签名 DMG，不增加 Apple 签名或公证要求

完整步骤见 [自动更新发布说明](./updates.md)。

## AI 对话

### 基本用法

1. 点击侧边栏 **会话** 进入对话页面
2. 在底部输入框输入消息，按 `Enter` 发送
3. AI 回复支持 Markdown、代码高亮、KaTeX 数学公式和 mhchem 化学式渲染
4. 使用 `Shift+Enter` 换行输入多行内容

### 会话管理

- **新建会话**: 点击聊天页左侧 "+" 按钮
- **切换会话**: 在会话列表中点击历史会话
- **搜索会话**: 使用搜索功能查找历史对话内容
- **导出会话**: 支持导出聊天记录
- **场景会话**: 场景实例会话会自动置顶；如果会话标题仍是内部 Agent ID，列表会优先显示 Agent 的可读名称

### 消息标注

聊天消息支持通用消息装饰：

- **验算徽章**: 当后端返回 `metadata.verify` 或 solve 结论时，消息顶部会显示已验算 / 不一致 / 超纲 / 无法验证等状态
- **入库徽章**: 当后端把某条结果写入记录集时，消息内会显示已保存到对应记录本及关键字段

这些徽章由通用契约渲染，不只服务某一个场景。

### 模型选择

支持以下 LLM Provider：

| 接入方式 | 配置前提 |
| --- | --- |
| OpenAI、DeepSeek、Anthropic、Gemini、通义千问、豆包等在线 Provider | 当前服务配置对应凭据与地址，并启用实际可用模型 |
| 自定义 OpenAI 兼容服务 | 对应服务的兼容接口地址、凭据及模型 ID |
| Ollama 本地模型 | 执行服务所在环境可访问 Ollama，并已下载所选模型 |

当前服务已有可用默认模型时，可直接发起任务。需要配置时，在 **设置 → LLM 配置** 中选择 Provider 和模型；在线模型填写所需 API Key 与地址，本地 Ollama 模型不需要云端 API Key。

### Quick Chat 快捷聊天

按 `⌘+Shift+H` (macOS) 或 `Ctrl+Shift+H` (Windows/Linux) 可在任意位置唤起快捷聊天窗口，无需切换到主界面即可快速提问。Quick Chat 使用与主聊天相同的 Auto-RAG 和模型参数透传能力。

## Agent 管理

### 创建 Agent

1. 进入 **智能体** 页面，点击创建智能体，选择从空白开始或套用模板。
2. 填写内部标识，按需要设置显示名称和人设（SOUL）。内部标识用于 `@` 引用与系统查找，创建后不能修改；显示名称可后续修改。
3. 按需要指定 Provider / 模型、推理策略、采样参数和技能；继承默认设置时可保留对应默认项。
4. 保存后，从智能体卡片进入该实例的会话。

### Agent 角色模板

内置多种预设角色：

| 角色 | 用途 |
|------|------|
| 通用助手 | 通用问答、任务规划和信息整理 |
| 客服助手 | 问题排查、话术应答和工单流转 |
| 内容创作 | 社媒文案、标题和话题建议 |
| 编程搭子 | 代码阅读、调试和命令执行 |
| 翻译官 | 多语种翻译和术语处理 |
| 日报助理 / 邮件助理 | 日报整理、邮件起草和回复 |
| 数据分析师 / 知识库问答 / 研究助理 | 数据解读、知识检索和资料研究 |
| 会议纪要 | 将已有讨论内容整理成纪要和待办 |

### 多 Agent 协作

通道消息可路由到指定 Agent，绑定和路由在“连接”中管理。多角色任务可使用工作流的并行扇出步骤调用配置角色并合并结果，具体操作见[工作流](#工作流工作流-tab)。

### 场景包模板

模板库除了通用角色模板，也可以显示场景包模板。当前内置的场景包模板是 **作业辅导助手**。

创建作业辅导助手：

1. 进入 **智能体** 页面
2. 在模板库选择 **作业辅导助手**
3. 填写孩子称呼、年级学期和教材版本
4. 保持默认辅导技能即可；高级区域可微调非必备技能
5. 创建后会生成一个专属 Agent 实例，显示名类似“孩子的辅导助手 · 五上”（像老师一样专业地帮家长辅导）

每个孩子建议创建一个独立实例。档案、错题本、积累本、学情和记忆都会按 Agent 实例隔离。

## 场景包与 K12 作业辅导

K12 作业辅导是当前内置场景包。它不是独立页面，而是一个 Agent 实例上的增强视图。

### 使用入口

创建作业辅导助手后，可以从两处进入：

- **智能体卡片**: 进入该孩子的辅导会话，查看这个实例的学习记录与报告
- **聊天页**: 选择对应辅导助手会话后，使用“辅导 / 学习档案 / 学情”查看任务与记录

### 辅导流程

在“辅导”Tab 中可以：

- 直接输入题目或粘贴作业照片
- 获取面向家长的讲题提示与完整解法，无需按三个阶段逐步解锁答案
- 可提供孩子的作答，让系统结合实际作答给出讲法
- 查看带证据类型的验算徽章，区分程序验算、模型复核、超纲和无法验证

发送作业图片后，任务自动完成识别、判定与结果生成，不需要确认识题结果或逐题点击批改。图片批改的主要产物是一张带批注的原图；处理中状态或文本说明不能替代最终图片。图片解题、作文点评和美术点评按对应任务返回结果。

经自动识别仍无法可靠辨认的内容，会在本次结果中标注“无法识别”，并作为任务终态的一部分；可识别题照常完成。不猜题、不编答案，也不把无法识别的题判错或写入错题、掌握度结论。用户可以自愿补拍，作为后续的新输入。

Provider 超时、调用结果未知、协议错误等技术失败会单独呈现，不会伪装成“无法识别”。结果未知时，不应反复发送同一请求。

桌面与已绑定钉钉通道使用相同的图片任务推进和终态。发送照片时无需选择“新作业”或“练习回传”；系统在当前孩子范围内关联可靠匹配的历史题目，无法可靠匹配时仍正常出图，不修改历史复习状态。

### 错题本、积累本和学情

在该孩子的“学习档案”和“学情”中查看：

- **错题**: 首屏以“本周该练”复习队列为主，展示到期该复习的题目、知识点、错因和复习状态，支持“再练一道”和“他会了”；“全部错题”作为可折叠档案，需要时再展开。也支持“记一条错题”手工录入，把线下作业、课堂上的错题一并归档
- **积累**: 收集语文 / 英语中的好词好句、古诗、语法点、作文素材等内容
- **学情**: 展示新增错题、复习完成率、薄弱知识点 TOP3 和连续挫败提示

复习记录与掌握状态分别保存，已复习不等于已掌握，答错仍待复习。只有实际覆盖且可靠判定的对应作答才积累复习证据；无法识别的内容不会计入，重放同一任务不会重复累积。

### 这份作业的辅导要点

任务返回「这份作业的辅导要点」时，内容直接显示在聊天流中，结合这份作业的题目、错题和学情说明“怎么教”；家长无需确认识题结果或主动打开独立面板。

辅导要点每个段落都会显示来源标注，例如：

- `📖 依据课本`
- `🗂 本地记录`
- `✅ 已程序验算`
- `🤖 AI 归纳·供参考`

内联的辅导要点支持复制文本，方便粘贴到手机 IM。

### 备份、导出和自动化

- 错题本可出“复习卷”：支持按到期复习队列组卷，以及按来源范围、题量、每来源变式数和难度自定义组卷；在产物预览中按提供的格式打印或导出
- 家庭学习档案可导出 `.hexbak` 归档并恢复，归档带版本头和校验和
- 建档后会尝试注册默认自动化任务；如果当前运行时未启用 cron，会静默降级，不影响建档
- 将家长与机器人的一对一私聊绑定到孩子的辅导实例后，该私聊消息按绑定路由；K12 不接收群聊绑定

## 知识中心

从侧栏“知识库”进入知识中心，在“文档”和“长期记忆”两个子页签间切换。

### 知识库（文档 Tab）

基于 RAG (Retrieval-Augmented Generation) 的知识管理：

#### 上传文档

1. 进入 **知识库** 页面，选择 **文档** 子页签，点击添加文档或上传文件。
2. 当前上传入口支持 PDF、Markdown、TXT、DOC/DOCX、PPTX、CSV、JSON/JSONL、HexBank，以及 PNG/JPEG/WebP/GIF 图片；具体处理能力取决于服务的解析与模型依赖。
3. 上传后查看持久化处理状态、原文与索引状态。图片需要可用视觉模型转写；向量索引需要可用 Embedding 服务。
4. 原文可读、关键词检索与向量检索分别核对；上传请求被接纳不表示所有处理已经完成。失败时使用文档的重试或恢复入口，保留已完成内容。

#### 使用知识库

当前 HexClaw 服务的引擎按知识库配置与任务策略检索资料，并将命中的证据加入模型上下文。是否检索、召回数量与相关度阈值由服务配置和任务决定；桌面不在发送消息前另行检索并拼接隐藏文本。命中资料时可在回答关联的来源信息中查看证据，具体呈现取决于该任务返回的结果。

支持对已有文档进行搜索和重建索引。

#### 文档详情查看

在文档列表中打开详情，系统通过当前服务的文档详情接口读取完整正文，并独立显示处理详情。正文读取失败时显示错误与重试入口；检索片段不拼接成“完整原文”，处理详情的局部失败也不替代原文读取结果。

### 记忆系统（记忆 Tab）

HexClaw 支持跨会话的长期记忆：

- **会话上下文** — 当前会话历史；启用压缩时按服务配置的消息阈值摘要旧消息并保留近期内容，不是固定 50 轮上限
- **长期记忆** — 跨会话持久化的知识和偏好
- **语义搜索** — 基于向量相似度检索相关记忆

在 **知识库 → 长期记忆** 中查看、搜索和管理持久记忆，并按需要调整记忆行为和用户画像。清空操作作用于当前选中的服务，请先确认需要删除的数据范围。

## 自动化

自动化页面集中管理定时任务、Webhook 和工作流，通过页内 Tab 切换。

### 定时任务（任务 Tab）

使用 Cron 表达式定期执行 Agent 任务：

1. 进入 **自动化** 页面，选择 **任务** Tab
2. 点击 "新建任务"
3. 配置：
   - **名称** — 任务描述
   - **Cron 表达式** — 如 `0 9 * * *` (每天 9:00)
   - **Prompt** — 要执行的 Agent 指令
4. 任务支持暂停/恢复/手动触发，可查看执行历史
5. 在应用内通知中心查看任务提醒，并在执行历史中核对实际输出

### 工作流（工作流 Tab）

使用有序步骤编辑 Agent 工作流：

1. 进入 **自动化** 页面，选择 **工作流** Tab
2. 新建工作流，或打开已有工作流
3. 添加并配置输入、模型处理、工具、并行扇出或输出步骤
4. 使用上移 / 下移调整执行顺序，然后保存
5. 点击“运行”，查看步骤状态和最终输出

当前桌面编辑器按步骤顺序建立线性连接；并行扇出步骤可调用多个配置角色后合并结果。它不是通过拖拽节点和手动连线编辑任意 DAG 的画布。

## 集成

侧栏“能力”页面统一管理工具集成，包含 Skills、MCP 和 Prompt 库三个子页签。

### Skill 系统（技能 Tab）

Skill 是 Agent 可调用的外部工具能力。

**已安装技能**: 查看和管理已安装的 Skill，支持启用/禁用。

**ClawHub 技能市场**: 浏览、搜索和安装社区贡献的 Skill，按分类筛选（编程/研究/写作/数据/自动化），支持一键安装/卸载。

### MCP 工具集成（MCP Tab）

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/) 是标准化的 AI 工具集成协议。

1. 进入 **能力** 页面，选择 **MCP** 子页签
2. 点击 "添加服务器"
3. 配置连接方式：
   - **stdio** — 本地进程通信
   - **SSE** — Server-Sent Events
   - **Streamable HTTP** — HTTP 流式传输
4. 连接成功后，该服务器提供的工具会自动注册到 Agent 可用工具列表
5. 支持查看工具列表和在线测试工具

### Prompt 库（Prompts Tab）

Prompt 库用于管理可复用的提示词模板。你可以创建、搜索和维护常用 Prompt，并在聊天输入中复用。

在“连接”中管理当前服务的 IM 通道，用于从桌面外部远程发起任务。

通过 IM 通道远程与 AI 对话：

1. 进入 **连接** 页面，管理 IM 通道
2. 点击 "添加通道"
3. 支持的 IM 平台：
   - **飞书** (Lark)
   - **钉钉** (DingTalk)
   - **企业微信** (WeCom)
   - **Slack**
   - **Discord**
   - **Telegram**
   - **微信** (WeChat)
4. 按所选平台填写应用凭据、接收方式与必要连接参数；不同平台的字段不同，配置参考 [HexClaw 消息渠道说明](https://github.com/hexagon-codes/hexclaw/blob/main/docs/install.md)
5. 支持在线测试通道连通性

图片任务通过已绑定通道进入相同的 Agent 执行链路，按任务回传批注图或其他实际产物，不另设识题确认步骤。通道连通性测试只说明连接状态；收到任务结果才说明该次业务完成。云端模式下，通道与任务由所选云端服务管理，服务器、模型与绑定持续可用时，电脑关机不会停止钉钉辅导。

## 设置与配置

设置页分为 **LLM 配置、自动化权限、系统设置** 三个区域。Webhook 在 **自动化 → Webhooks** 管理，长期记忆在 **知识库 → 长期记忆** 管理。

### LLM 配置

| 选项 | 说明 |
|------|------|
| Provider | LLM 服务商 |
| 默认模型 | 从已启用模型中选择当前服务的默认聊天模型 |
| 模型管理 | 获取模型目录、添加自定义模型，并启用或停用所需模型 |
| API Key | 服务商 API 密钥 |
| Base URL | 自定义 API 端点 (可选) |
| 测试连接 | 检查 Provider 的接口连接；任务是否完成仍以实际回答或产物为准 |

### 自动化权限

在 **设置 → 自动化权限** 中选择功能优先、严格审批或全功能级别，并查看待处理任务、任务级授权、审计记录和生效策略矩阵。全功能需要额外确认；具体任务审批在创建流程或任务卡片中完成。

权限放行不代表模型、连接器或外部服务可用，也不代表任务已经成功。自动化执行状态与结果在 **自动化** 页面查看。

### 系统设置

- **主题模式**：浅色 / 深色 / 跟随系统，切换后即时生效
- **语言与启动**：选择界面语言，设置开机自启动
- **本机与云端服务**：查看连接状态并管理后端服务
- **运行选项**：长期记忆与沙箱网络开关
- **系统信息**：查看版本、存储文件、知识索引和 API 地址

### 通知

应用内通知中心汇总待审批、任务结果、通道消息和服务状态变化，可标记已读并跳转到相关页面。业务通知同时可通过应用内提示呈现；当前设置页不提供独立的通知或声音开关。

### 运行引擎 (Runtime Engine)

在“设置”的服务卡片中查看当前选择的本机或云端服务及连接状态；在“关于”页面查看桌面、后端与组件版本。Hexagon 与 ai-core 是后端依赖的引擎和能力库，不是需要分别启动的独立服务。

服务连接正常不代表所选模型、知识处理或投递任务已经成功，仍需核对对应任务的实际结果。

桌面管理本机 Sidecar 的生命周期；云端服务由服务器管理。切换服务不迁移会话、学习记录、模型配置或通道绑定。

## 故障排查

### 引擎状态红灯 (Engine stopped)

**原因**: 当前选中的 HexClaw 服务未就绪。本机模式可能是 Sidecar 未启动或不健康；云端模式应检查服务地址、访问令牌和服务器可用性。

下面的进程与端口检查仅适用于本机服务。云端服务无需在本机启动 Sidecar，桌面也不会重启云端进程。

**排查步骤**:

```bash
# 1. 检查进程是否在运行
ps aux | grep hexclaw

# 2. 检查端口监听
lsof -i :16060

# 3. 手动测试健康检查
curl http://localhost:16060/health
# 应返回: {"status":"healthy"}
```

**常见原因**:
- 端口 16060 被其他进程占用
- hexclaw 二进制文件不存在或损坏
- 权限问题（macOS 安全策略拦截）

### 对话无响应

1. 确认引擎状态为绿灯 (Engine running)
2. 确认当前服务配置了可用模型；在线模型需对应 Provider 凭据，本地模型需可用的 Ollama 与已下载模型
3. 检查执行服务到所选模型的连接
4. 查看日志页面获取详细错误信息

### 应用崩溃

查看系统日志：
- macOS: `Console.app` → 搜索 "HexClaw"
- 或直接从终端启动查看日志：

```bash
# macOS
/Applications/HexClaw.app/Contents/MacOS/hexclaw-desktop

# 查看本机 Sidecar 日志
tail -n 100 ~/.hexclaw/hexclaw.log
```

### 重置应用数据

以下为 macOS 的完整本机重置。先退出 Desktop、停止使用同一数据目录的 HexClaw 服务，并备份需要保留的数据。

> **警告**：下面的命令会删除本机对话、Agent、模型配置、记忆及桌面连接信息，无法直接撤销；不会删除云端服务保存的数据。

```bash
# 删除应用数据
rm -rf ~/.hexclaw

# 删除桌面应用数据
rm -rf ~/Library/Application\ Support/com.hexclaw.desktop
```

## 选择任务执行环境

HexClaw Desktop 适合希望在原生工作台中统一使用对话、知识、工具、自动化与作业辅导的用户。先根据任务选择执行位置：

| 需要 | 配置方式 |
| --- | --- |
| 在当前电脑执行任务 | 使用应用管理的本机 Sidecar，并配置该设备可用的模型与工具 |
| 电脑关机后仍由服务器执行任务 | 部署云端 HexClaw，配置服务器的模型、工具和 IM 绑定，再通过服务地址与令牌连接 |
| 使用在线模型 | 执行服务需要对应凭据和网络；Provider 会接收发送给它的任务内容 |
| 使用本地模型 | 执行服务需能访问 Ollama 和已下载模型；工具与文档渲染仍需各自的依赖 |

本机和云端分别保存会话、记录、配置与连接，切换服务不会自动同步或迁移。多个设备连接同一云端服务，不等于已经提供团队管理或跨设备同步功能。

如需比较 [OpenClaw](https://github.com/openclaw/openclaw) 等其他项目，请以对应项目当前官方文档核对功能、安装和使用边界。本指南只维护 HexClaw 的实际实现与操作入口。
