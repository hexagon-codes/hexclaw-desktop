# HexClaw Desktop 产品总览

如果你第一次接触 HexClaw，建议先看这张总览图，再继续看详细使用指南。

![HexClaw Desktop 架构泳道图：工作台连接本机或云端服务](../.github/assets/desktop-architecture.svg)

## 这是什么

HexClaw 是原生 AI Agent 工作台，可连接应用管理的本机服务或自己部署的云端服务。`会话`、已绑定的 `IM 通道` 和 `自动化` 是任务入口，`知识库 / 智能体 / 能力 / 场景包` 提供能力，`日志` 用于诊断与排查。

如果只记一句话，可以先记这个：

**先选择服务并确认可用模型，再从聊天、IM 或自动化发起任务，按需要接入知识、智能体、工具与场景能力，通过实际结果和日志确认任务完成。**

## 第一次打开应该怎么用

建议按下面的顺序开始：

1. 选择本机服务，或填写云端 HexClaw 的服务地址和访问令牌
2. 已有可用默认模型时直接使用；未配置时再设置 Provider 和模型。在线模型填写所需凭据与地址，本地模型确认 Ollama 与已下载模型可用
3. 在 `会话` 发起第一轮任务，以收到完整回答或实际产物确认完成；连接测试通过不能代替任务结果

本机 Sidecar 由桌面管理，云端服务由服务器管理；云端模式不要求启动本机 Sidecar。两种服务分别保存数据，切换不自动迁移。AI 任务需要可用模型，无模型时仍可查看配置与管理基础资料。

## 主模块分别负责什么

### 会话

`会话` 是桌面打开后的默认首页，也是主要任务入口。

你可以在这里完成：

- 普通多轮对话
- 文档和附件输入
- Markdown / 数学公式 / 化学式渲染
- Artifact 查看
- 研究模式任务
- 场景实例增强视图（例如作业辅导的辅导 / 错题本切换、识题后内联的辅导要点、验算徽章和入库提示）

### IM 通道

`IM 通道` 是桌面外部的消息入口，负责把飞书、钉钉、Discord、Telegram 等接入到 HexClaw。

它既可接收外部消息发起任务，也可回传回答、文件或自动化结果；具体传输能力取决于所选通道。

### 知识库

`知识库` 负责管理文档和记忆，为聊天和智能体提供检索上下文。

知识检索与上下文注入由当前 HexClaw 服务的引擎统一处理，根据知识库配置与检索结果提供上下文；桌面不另外检索后拼接隐藏的知识文本。

它解决的是“模型不知道你的私有资料”这个问题。

### 智能体

`智能体` 负责管理角色模板、已注册 Agent 和默认 Agent。通道与 Agent 的绑定及消息路由在 `连接` 页面管理。

它解决的是“谁来做这件事、按什么角色做、不同场景如何分流”。

### 场景包

`场景包` 不是新的一级页面，而是挂在 Agent 实例上的增强能力。

当前代码内置的场景包是 `作业辅导助手`。在 `智能体` 模板库里建档后，它会生成专属 Agent 实例；进入该实例后，可在辅导、学习档案与学情中查看任务产物、学习记录和报告。辅导要点、错题入库提示和验算徽章按任务结果展示。

通用工作台保留统一的会话与导航入口，场景实例在会话内展示对应领域视图；可用任务与记录以实际场景能力为准。

### 能力

`能力` 页面负责管理 Skill、MCP 服务和 Prompt 库。

这里的 `MCP` 是 `Model Context Protocol`，作用是把外部工具和服务接给 AI，例如：

- 数据库
- 浏览器能力
- 文件系统
- 内部服务
- 命令行工具

这意味着 HexClaw 里的 AI 不只是“生成答案”，还可以“调用能力”。

### 自动化

`自动化` 管理定时任务、Webhook 和工作流。当前桌面工作流使用有序步骤编辑，按步骤配置、调整顺序并执行。

它解决的是“任务不一定等用户来点，也可以自己按计划运行”。

### 日志

`日志` 是运行结果和异常的统一排查入口。

如果 IM 没回、知识库没命中、工具没调通、任务没执行，最终都应该回到这里看。

## 模块之间怎么协同

把系统理解成一条主链路最容易：

![HexClaw Desktop 任务泳道图：入口、执行、能力与结果交付](../.github/assets/desktop-task-workflow.svg)

这条链路对应的用户理解是：

- `会话` 是桌面里的主要任务入口
- `IM 通道` 是桌面外部的消息入口
- `自动化` 会按计划主动触发任务
- 这些入口最终都会进入统一执行链路
- 执行链路再去调用知识库、智能体、工具集成和场景包能力
- 执行结果和异常最终沉淀到日志

## 聊天和 IM 能不能“指挥其他模块”

可以，但要把“任务入口”和“配置页面”分开理解。

更准确的理解方式是：

- `会话 / IM` 负责发起任务
- `知识库 / 智能体 / 能力 / 场景包` 负责提供能力
- `设置 / 自动化管理 / 知识库管理 / MCP 管理` 这类页面负责完成配置

所以 HexClaw 不是“聊天直接管理所有功能”，而是“聊天通过执行链路调用其他能力”。

## 推荐的理解顺序

如果你第一次接触 HexClaw，建议按这个顺序理解：

1. 先把它看成一个连接本机或云端服务的原生 AI 工作台
2. 再把 `会话` 和 `IM 通道` 看成任务入口
3. 再把 `知识库 / 智能体 / 能力 / 场景包` 看成能力底座
4. 再把 `自动化` 看成主动运行能力
5. 最后把 `日志` 看成问题排查闭环
