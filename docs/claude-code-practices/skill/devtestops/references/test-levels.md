# 变更类型→测试级别映射与提测准入基线

本表是方法索引，不是必跑矩阵。先按用户意图、受影响行为、现有证据和缺口选择最小充分方法；当前项目授权、禁令与固定 CI 优先。新增测试先确认具体意图，整体测试先评估必要性。HexClaw 不运行压力、负载或 soak，不安排通用安全专项，UI 验证默认人工；下文其他项目的候选方法不解除这些约束。

## 变更类型判定规则

结合 `git diff`、实际调用与业务合同判断影响；文件类型或数量不能单独决定测试范围：

| 变更类型 | 判定标准 |
|---------|---------|
| 纯逻辑调整 | 仅修改单文件/单函数内部逻辑，不涉及接口签名、跨模块调用或数据模型变更 |
| 接口改动 | 新增或修改 API 端点、请求/响应字段、错误码、鉴权方式 |
| 跨模块改动 | 变更涉及 2 个以上模块/包，或修改了共享数据模型、公共工具函数 |
| 核心链路改动 | 变更涉及登录/鉴权、下单/支付、任务提交/回调等核心业务入口 |
| 高风险改动 | 涉及数据迁移、架构重构、并发模型变更、第三方服务切换 |

## 测试级别定义

### 单元测试（P0）

覆盖最小可测单元的正常/异常/边界路径。

**测试框架**：根据项目技术栈自动识别（Vitest / Jest / pytest / Go test 等）

**覆盖要求**：
- 函数/方法的正常输入 → 正确输出
- 边界输入：空值、零值、超长、非法格式、特殊字符
- 异常路径：错误输入、非预期状态、字段缺失
- 状态流转：合法状态切换 + 非法状态处理

**Claude Code 执行方式**：
- 在授权内执行选定的已有测试文件或包；只有整体必要性成立时才运行全量命令
- 定向阅读与调用证据用于定位缺口，搜索命中不代表需要新增测试

### 模块测试（P0）

组件/模块与直接依赖的联动行为。

**覆盖要求**：
- 组件 + Store/State 联动
- 组件 + 路由守卫联动
- Service + Repository 联动
- 中间件/拦截器行为验证

### 接口/API 测试（P1）

**覆盖要求**：
- 入参校验（必填、类型、格式、长度）
- 出参结构（字段完整性、类型正确性）
- 状态码和错误码
- 鉴权/权限（未登录、越权、角色差异）
- 幂等性（重复请求）
- 分页和过滤逻辑
- 兼容性（老字段不删、新字段有默认值）

**Mock 契约验证**（Demo/前端项目）：
- Mock 数据字段与 PRD 数据模型一致
- Mock 文件有 @prd 标注
- 调用处有 TODO[接入] 标注
- TypeScript 类型定义与 PRD 对齐

### 集成测试（P1）

**覆盖要求**：
- 跨模块调用链完整跑通
- 数据在模块间正确传递
- 事务一致性（DB 事务成功/失败/回滚）
- 缓存与 DB 一致性
- 消息队列生产者→消费者

### E2E 测试（P2）

**覆盖要求**：
- 从真实入口走完整业务流程
- 浏览器/客户端级别操作
- 跨页面/跨服务的状态流转
- 响应式布局验证

**Claude Code 执行方式**：
- 使用 Playwright MCP 进行浏览器自动化
- 使用 Browser MCP 进行截图比对

### 系统测试（P2）

**覆盖要求**：
- 跨模块业务流程闭环（如：注册→审核→登录→使用）
- 多角色交叉操作
- 数据隔离验证

### 安全测试（P1）

**覆盖要求**：
- XSS 防护（输入转义、输出编码）
- 注入防护（SQL 注入、命令注入）
- 权限绕过（URL 篡改、角色提权）
- 会话管理（持久化、过期、多标签同步）
- 敏感信息泄露（密码明文、日志、URL、响应体）

### 兼容性与回归测试（P2）

**覆盖要求**：
- 历史数据兼容（老数据不报错）
- 浏览器兼容（Chrome / Firefox / Safari）
- 移动端兼容
- 修复后回归不引入新问题

### 性能/基准测试（P2）

**覆盖要求**：
- 关键路径响应时间基线
- 并发压力下的稳定性
- 内存/CPU 使用无异常增长

## 提测准入基线

| 变更类型 | 优先考虑的方法 | 需要具体依据的补充 | 判定依据 |
|---------|---------|---------|---------|
| 领域规则与算法 | 直接单元或组件验证 | 实见边界与异常 | 对应规则是否有充分证据 |
| 公共 API | 真实 API/契约验证 | 受影响的错误、归属与兼容边界 | 请求与实际结果是否符合合同 |
| 事务与持久化 | 真实数据库依赖 | 已证实的并发、回滚或恢复 | 数据不变量是否得到证明 |
| 真实用户装配 | 必要 E2E | 原生、渠道与实际产物 | 是否覆盖不可替代的用户边界 |
| 性能或发布问题 | 指定瓶颈或发布入口 | 经授权的定向测量与恢复演练 | 具体目标与停止条件是否满足 |
